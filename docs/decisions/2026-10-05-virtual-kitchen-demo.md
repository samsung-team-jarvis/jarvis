# Decision: 시연 환경은 가상 주방(메타버스), 장치 8종

## Status
- Accepted ([안전 3계층](./2026-10-01-safety-layers.md)의 L0 위치와 [Function Call 스키마](./2026-10-02-function-call-schema.md)의 장치 범위를 바꾼다. 두 결정의 정책 자체는 그대로다)

## Date
- 2026-10-05

## Context
- 지금까지의 계획은 실물 모형이었다: ESP32 + BLE로 저전압 모형(LED·USB 팬·릴레이)을 움직이고, USB 웹캠과 열전대·전류 센서로 상황을 본다 (작업물 ④, HW-01~12).
- 2026-10-05 기준 하드웨어 작업은 시작 전이다. 부품을 사지 않았고 모형도 없다. Gate 2("말 → LED")가 여기서 막혀 있다.
- 등록된 프로젝트명은 "스마트 자영업 서비스 어시스턴스: 자비스"다. 주방 장치 3종(후드, 화구 2개)만으로는 매장 운영을 돕는다는 주제를 보여 주기 어렵다.
- 과열·방치 같은 위험 상황은 모형으로도 반복해 만들기 어렵다.

## Options
- Option A: 실물 모형 유지 (ESP32·BLE·웹캠·센서)
- Option B: 가상 주방(메타버스)에서 시연. 장치·카메라·온도가 모두 가상이고, 음성만 실제 마이크로 받는다
- Option C: 실물 모형 + 가상 화면을 함께 쓴다

## Decision
- 선택한 안: **B** (결정: 이현종)

| 항목 | 결정 |
|---|---|
| 시연 환경 | 가상 주방(메타버스). **실물 제어 하드웨어는 없다** (ESP32·BLE·모형·웹캠·온도·전류 센서를 쓰지 않는다) |
| 음성 | 실제 사람이 실제 마이크로 말한다 (변경 없음) |
| 카메라 | 가상 주방 안에 고정한 인식용 카메라의 화면을 캡처해 보드로 보낸다 |
| 온도 | 가상 주방이 가열 장치의 세기와 시간으로 계산해 보드로 보낸다 |
| 추론 | 모두 보드(Orange Pi)에서 한다 (변경 없음). 가상 주방은 PC에서 돈다 |
| 플랫폼 | **미정** ([open-questions](./open-questions.md) Q-11) |
| 장치 | 8종: 화구(1번·2번), 튀김기, 후드, 조명, 에어컨, 선풍기, 음악, 결제시스템 |
| 환풍기 | 후드와 같은 장치다 (부르는 말만 다르다) |
| 결제시스템 | 결제 요청, 금액 확인 두 가지. 결제 요청은 금액을 말해 주고 확인을 받은 뒤 실행한다 |

- 선택 이유: 하드웨어 작업이 시작 전이라 바꾸는 비용이 작다. 위험 상황을 실제 위험 없이 같은 조건으로 되풀이할 수 있다. 매장 장치를 부품 없이 늘릴 수 있다. 프로젝트의 핵심(보드 안에서 음성·화면·온도를 함께 보고 판단)은 그대로다.
- **안전 3계층은 유지한다.** L0(ESP32 펌웨어)의 역할을 가상 주방 쪽 안전장치가 맡는다: 보드의 생존 신호가 끊기거나 온도 상한을 넘으면 가상 주방이 스스로 가열 장치를 끈다. L1(Safety Guard)·L2(LLM은 제안만)는 변경 없다.

## Consequences
- 장점: 부품 구매·배선·펌웨어 작업이 없어진다. 과열·방치 시나리오의 재현성이 높다. 화면 데이터를 빠르게 모을 수 있다.
- 단점:
  - 가상 화면으로 학습·평가한 비전 정확도는 가상 주방 안에서만 유효하다. 실제 주방 카메라에서의 정확도는 확인하지 않는다.
  - 온도는 계산한 값이다. 실제 센서의 잡음·지연은 다루지 않는다.
  - 플랫폼에 따라 보드와 잇는 방식, 화면 캡처 방법이 달라진다 → 플랫폼을 먼저 정해야 ④의 작업이 구체화된다.
  - **이미 만든 것에 영향**: Function Call 스키마 v0.1, 규칙 파서, 응답 문장, LLM 데이터 v1, 기준선 측정값은 모두 장치 3종 기준이다. v1에서 "조명 켜줘"·"에어컨 꺼줘"·"볼륨 줄여 줘" 같은 22문장은 "지원 외"가 정답인데 장치를 늘리면 정답이 바뀐다 → 스키마 v0.2와 데이터 v2로 다시 만들고 다시 잰다 (LLM-13·14).
- 영향:
  - [PLAN](../PLAN.md): HW-01~12 취소 → 가상 주방 작업 HW-13~23, LLM-13·14 추가, Gate 0·1·2 조건, BOM
  - [overview](../architecture/overview.md), [hardware](../architecture/hardware.md), [interfaces](../architecture/interfaces.md) (v0.2 예정 변경으로 기록), [METRICS](../METRICS.md), [budget](../budget.md)
  - 바뀌지 않는 것: 메시지 봉투와 버스(MQTT), `stt/text`·`llm/function_call`·`guard/decision`·`control/command`, 음성 서비스, 측정·녹음 도구, 데이터 파이프라인(시트만 고쳐 다시 생성)

## Verification
- Gate 2: "자비스, 후드 켜줘" → 가상 주방의 후드가 켜짐 (PLAN)
- 제어 성공률·왕복 지연, 생존 신호 끊김 시 안전 정지 ([METRICS](../METRICS.md))

## Revisit
- 플랫폼을 정했는데 보드와 메시지를 주고받을 수 없거나 화면을 캡처할 수 없을 때 → [simulator](../../services/simulator/README.md)(가짜 메시지)와 로컬 화면으로 시연하는 안을 검토
- 실물 장치 시연이 다시 필요해질 때
