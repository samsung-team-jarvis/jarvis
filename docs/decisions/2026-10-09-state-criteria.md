# Decision: 주방 State 정답 기준과 온도 시나리오 (FUS-05)

## Status
- Accepted (시연용 설계값 — 가상 주방에서 써 보고 조정한다)

## Date
- 2026-10-09

## Context
- State 6개(`IDLE, PREHEAT, COOKING, UNATTENDED, DANGER, SAFE_STOP`)는 FUS-01에서 정했지만, 전이 조건은 FUS-05에서 정하기로 남겨 두었다 (interfaces §2.3).
- 주의·위험 온도(200°C·240°C 후보)와 방치 판단도 FUS-05에서 확정하기로 했다 (interfaces §4.5).
- 상황 인식 Baseline(FUS-07)과 State Machine(FUS-08)의 State F1·위험 미탐율을 재려면, 시나리오마다 "그 시각의 정답 State"가 있어야 한다.
- 가상 주방 온도는 실제 조리 온도가 아니라 과열을 1분 남짓에 재현하도록 정한 설계값이다. 1초마다 목표와의 차이의 5%씩 다가가고, 목표는 세기 1·2·3 → 120·180·270°C다. 265°C에서는 가상 주방이 스스로 끈다 (L0).

## Options
- 정답을 붙이는 방법: (A) 실제 장치 상태(켜짐·세기·온도·사람·조리 도구)에 기준을 적용해 생성 코드가 붙인다 / (B) 사람이 시나리오마다 손으로 적는다
- 시나리오 형식: (A) simulator 시나리오 YAML에 `category`·`expect` 필드를 더한다 / (B) 정답을 별도 파일로 둔다

## Decision
- 선택한 안: 정답 A, 형식 A (결정: 최지환)

| State | 정답 기준 (위가 먼저) |
|---|---|
| `SAFE_STOP` | 긴급 정지 또는 가상 주방 안전장치(265°C)로 꺼진 뒤, 가열 장치를 다시 켜기 전까지 |
| `DANGER` | 가열 장치가 켜져 있고 온도 ≥ **240°C** |
| `UNATTENDED` | 가열 장치가 켜져 있고 사람이 **30초** 이상 안 보임, 또는 화구 위에 조리 도구가 **60초** 이상 없음 (튀김기는 기름이 늘 있어 조리 도구 조건 없음) |
| `PREHEAT` | 가열 장치가 켜져 있고 온도 < **100°C** |
| `COOKING` | 가열 장치가 켜져 있고 온도 ≥ 100°C |
| `IDLE` | 가열 장치가 꺼져 있음 |

- **주의 200°C**는 State를 바꾸지 않고 `fusion/state`의 `risk: warn`으로만 쓴다. `DANGER`면 `risk: danger`다.
- PREHEAT 경계를 100°C로 둔 이유: 약불(세기 1)의 목표 온도가 120°C라서, 경계가 그보다 높으면 약불 조리가 영원히 예열로 남는다.
- 위험이 방치보다 먼저다. 자리를 비운 사이 과열되면 `DANGER`다.
- 시나리오 25개(`services/simulator/scenarios/temp/`)는 `services/simulator/temp_scenarios.py`가 사건 목록으로 만든다. 정상 8 · 과열 6 · 방치 6 · 가열 장치 켜짐 방치 5이고, 각 분류에는 위험이 나오면 안 되는 비교용 시나리오(짧게 자리 비움, 팬을 잠깐 듦 등)가 섞여 있다.
- 선택 이유:
  - 손으로 적은 정답은 기준과 어긋나기 쉽다. 기준을 코드로 두면 기준을 바꿀 때 25개 정답이 같이 바뀐다.
  - 정답은 상황 인식이 볼 수 없는 실제 상태로 붙인다. 상황 인식은 메시지(온도·화면·말)만 보고 맞혀야 하므로 F1이 의미를 가진다.

## Consequences
- 장점: State F1·위험 미탐율의 기준이 생겼다 (FUS-07). simulator로 바로 재생할 수 있어 가상 주방 없이 상황 인식을 개발할 수 있다.
- 단점: 모두 설계값이다. 시나리오의 시간(센불 41초에 240°C 등)은 가상 온도 규칙이 바뀌면 다시 만들어야 한다 (`--check` 테스트가 알려 준다). 가열 장치 하나씩만 다룬다 (simulator 센서가 장치 하나).
- 영향: [interfaces](../architecture/interfaces.md) §2.3·§4.5, [simulator](../../services/simulator/README.md), PLAN FUS-05·07·08·09

## Verification
- `tests/simulator/test_temp_scenarios.py`: 파일이 생성 코드와 같음, 개수·분류, 정상 시나리오에 위험·방치 없음, 과열 시나리오에 DANGER 있음, 기준 예시(30초 방치, 60초 빈 화구, 위험 우선, 튀김기 예외)

## Revisit
- 가상 주방(HW-19)에서 온도 곡선을 실제로 본 뒤 (240°C까지 41초가 시연에 맞는지)
- FUS-07·08에서 비전·온도만으로 이 기준을 맞히기 어려운 부분이 나올 때 (예: 조리 도구 인식)
