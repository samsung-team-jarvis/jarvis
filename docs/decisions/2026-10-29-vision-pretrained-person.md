# Decision: 비전은 사전학습 YOLOv8n의 사람 감지부터, 맞춤 학습은 화면 캡처가 생기면

## Status
- Proposed — 비전 클래스 담당(최지환, VIS-02)·화면 캡처 담당(최석진, VIS-03·04) 확인 후 Accepted

## Date
- 2026-10-29

## Context
- 맞춤 클래스(팬·냄비·화구 켜짐/꺼짐·튀김 바구니·뒤집개·손, interfaces §2.1 후보)를 학습하려면 가상 주방 화면 캡처 800~1,200장과 라벨이 필요하다 (VIS-03·04). 캡처가 오지 않을 수 있다 (2026-10-29).
- 상황 인식에서 화면이 꼭 알려 줘야 하는 것은 **조리 구역에 사람이 있는가**다 — 방치 = 가열 장치 켜짐 + 사람 없음 (simulator `unattended.yaml`). 가열 장치가 켜졌는지는 보드가 이미 안다 (`kitchen/state`, 보낸 제어 명령, 온도).
- COCO 사전학습 YOLOv8n은 `person`을 학습 없이 잡는다. rknn_model_zoo가 같은 모델의 RK3588용 ONNX(출력 9개)와 변환 절차를 제공하고, 우리 RKNN 변환도 이 모델로 성공했다 (#13).

## Options
- Option A: 캡처를 기다려 맞춤 클래스를 학습한다
- Option B: **사전학습 모델의 `person`(필요하면 COCO의 주방 물체 몇 개)으로 먼저 만들고, 캡처가 생기면 맞춤 모델로 바꾼다**
- Option C: 비전을 빼고 온도·제어 기록만으로 상황을 판단한다

## Decision
- 선택한 안: **B** (제안: 이현종)
- `vision_svc`는 rknn_model_zoo 형식의 YOLOv8n ONNX를 쓴다. 기본 발행 클래스는 `person` 하나. 클래스 이름은 COCO 이름을 그대로 쓴다.
- 입력은 가상 주방 화면(`kitchen/frame`)이 기본이고, 없으면 노트북 카메라·이미지 폴더. 노트북 시연에서는 카메라 앞의 사람이 조리 구역의 사람 역할을 한다.
- 맞춤 학습 경로(VIS-03·04·06·07·09, 학습 노트북 VIS-10)는 그대로 두고 **캡처가 생기면** 진행한다. 맞춤 모델도 같은 출력 형식으로 export하므로 서비스 코드는 그대로다.

## Consequences
- 학습 데이터 없이 방치 판단에 필요한 신호가 생긴다. 노트북 CPU 2스레드에서 장당 약 76 ms (Mac 참고값, 1초에 4장 처리 가능).
- 잃는 것: 팬·화구 같은 조리 물체를 화면에서 직접 보지 못한다. "화구 켜짐"은 화면 대신 장치 상태로 판단한다.
- 사전학습 모델의 가상 주방(3D 렌더링) 속 사람 인식률은 측정 전이다 — 실사 사진으로 학습된 모델이다.
- 모델 가중치(Ultralytics YOLOv8, AGPL-3.0)는 저장소에 올리지 않고 받아 쓴다.
- 영향: [interfaces](../architecture/interfaces.md) §2.1, [PLAN](../PLAN.md) VIS-02~09, [vision_svc](../../services/vision_svc/README.md)

## Revisit When
- 가상 주방 화면 캡처가 200장 이상 생길 때 (맞춤 학습 시작)
- 사전학습 모델이 가상 주방 화면의 사람(아바타)을 잘 못 잡을 때
