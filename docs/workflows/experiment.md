# Experiment & Measurement

이 과목의 핵심 산출물은 "Baseline → 개선 → 같은 Test Set 재평가" 결과다 (5주차 발표 p.12~14).
모든 측정은 이 절차를 따른다. 결과는 [METRICS](../METRICS.md)에 기록한다.

## 원칙

1. **실측만 기록한다.** 추정·가정 수치는 쓰지 않는다. 미측정은 `측정 예정`.
2. **Test Set은 고정한다.** 오류 분석은 Validation으로 하고, Test는 비교할 때만 쓴다.
3. **분할은 그룹 단위.** 화자(`speaker_id`)·촬영 세션(`session_id`)·템플릿(`template_id`)·시나리오(`scenario_id`)가 Train과 Test에 함께 들어가지 않게 한다.
4. **최종 판정은 보드 기준.** 서버·Mac 수치는 참고용으로 따로 표시한다.
5. **보드 측정 전 클럭을 고정한다** (`sudo bash fix_freq_rk3588.sh`). 고정하지 않으면 같은 모델도 측정마다 속도가 달라진다 (학교 특강2 p.28~29).
6. **재현 가능해야 한다.** 측정 조건(보드, 툴 버전, 모델 파일, 데이터셋 버전, 커밋, 실행 명령)을 함께 남긴다.

## 절차

```text
1. 실험 계획    templates/experiment.spec.md 복사 → 이슈에 첨부 또는 training/·bench/에 저장
2. Baseline 측정 (개선 전 동일 조건)
3. 변경 적용    (데이터 추가, 학습, 양자화 설정, 전처리 등 — 한 번에 하나씩)
4. 재측정       같은 Test Set, 같은 측정 스크립트
5. 기록         METRICS 측정 로그 + 결과표, PR Measurement 섹션
6. 오류 분석    Validation 오류 유형 분류 → 다음 사이클 이슈 생성
```

## 지표별 주의

- 한국어 STT는 WER보다 **CER**을 주지표로 쓴다. 띄어쓰기 때문에 WER이 왜곡된다.
- LLM은 서버 기본 모델 / 서버 학습 모델 / 보드 양자화 모델 3단계를 같은 문항·같은 템플릿·greedy decoding으로 비교한다.
- 지연은 구간별로 쪼개서 잰다 (전처리 / 추론 / 후처리 / 전송). 평균과 함께 p95를 남긴다.
- 양자화 전후 비교는 같은 Test Set으로 한다. 캘리브레이션 데이터는 Train에서만 뽑는다.
