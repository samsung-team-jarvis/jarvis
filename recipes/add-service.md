# Recipe: 새 서비스 추가

> 첫 서비스(INFRA-03 이후)를 만들면서 실제 디렉터리 구조와 명령으로 갱신한다.

## 절차

1. **spec 작성**: `templates/service.spec.md` 복사 → 입력 토픽, 출력 토픽, 설정값, 실패 시 동작.
2. **규격 확인**: 주고받는 메시지가 [interfaces](../docs/architecture/interfaces.md)에 있는지 확인. 없으면 interfaces를 먼저 고친다 (변경 이력 기록).
3. **디렉터리**: `services/<name>/` 아래에 진입점, 설정 파일, `README.md`(실행 방법 3줄).
4. **입력 교체 가능하게**: 실제 장치 / 파일 / 가짜 메시지 중 선택해 실행할 수 있게 만든다 → 하드웨어 없이 Mac에서 개발 가능.
5. **공통 모듈 사용**: 메시지 생성·발행·구독은 `common/`만 사용. 로그는 `common` 로거.
6. **하트비트**: `system/heartbeat`를 주기적으로 발행.
7. **측정 필드**: 처리 시간(ms)을 payload에 포함 (interfaces 토픽 표 참고).
8. **확인**:
   - 가짜 입력으로 출력 토픽이 나오는지 (`recorder` 로그 또는 구독 도구)
   - 서비스가 죽었다 살아나도 다른 서비스가 계속 동작하는지
9. **런처 등록**: 일괄 기동 스크립트(BOARD-07)에 추가.
